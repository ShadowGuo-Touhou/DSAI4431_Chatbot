# 技能手册（SOP）

这一份是「怎么做」：遇到什么类型的请求，按什么顺序检索、按什么清单核对、按什么格式回答。
事实与数值一律来自知识库（官方 wiki 0.6.2.6），这里只写流程和判定标准。

## 技能 0：先判类型

| 用户想要 | 用哪个技能 |
|---|---|
| 某个部件/舰体/弹药的具体数值 | 技能 1 |
| 「有哪些 / 分几类 / 列表」 | 技能 2 |
| 配一艘船、改一艘船、这艘船值不值 | 技能 3 |
| `.fleet` 文件、整套舰队的评审 | 技能 4 |
| 机制、战术、术语、软杀、穿甲 | 技能 5 |
| 知识库里查不到 / 非游戏问题 | 技能 6 |

一次检索最多 2 次；第 2 次之后必须给出回答，并说明还缺什么。

## 技能 1：单件查询

1. 检索词 = 官方英文名 + 类别词（`compartment` / `module` / `mount` / `munition`）。
2. 回答必须包含 **全部** 数值，不要只挑一两个：Dimensions、Hitpoints、Damage Threshold、Mass、
   Required Power（或 Power）、Cost、Missile Size、Capacity、Commands Enabled、Role 等，凡是知识库
   里该部件有的都要列。
3. 每条数值后面标来源文件（例如 `component/vls-2-launcher.md`）。
4. 顺手说明它的 Tag 含义：kind（mount/module/compartment）、type（例如 weapon support）、
   role、资源效果（provide/consume power、provide command）。

## 技能 2：列举类问题

1. 「有哪些 X」直接检索 `catalog/<kind>.md`（整类一张表）或 `<类别>/_index--*.md`（单个分区一张表）。
2. 先给总数，再给表；表列固定为：名称 / 类型 / 关键数值 / 点数。
3. 一条都不能漏：catalog 里有多少行就写多少行。超过 20 行按 type 分组。
4. 如果用户问的是「能装什么」而不是「有哪些」，补一句槽位类型限制（Mount / Compartment / Module）
   和知识库里有没有该船的槽位布局（没有就直说）。
5. **阵营问题**（「哪些只有 OSP/SA 能用」「这个部件属于哪个阵营」）检索
   `catalog/faction-osp.md`、`catalog/faction-sa.md`、`catalog/faction-both.md`。判定规则：
   `faction=Shelter Alliance (SA)` 表示只能装在 SA 船上，`faction=Outlying Systems Protectorate (OSP)`
   只能装在 OSP 船上，标了两个阵营或**没有 faction 标签**表示两阵营通用。
   `observed-faction=…` 只是你自己的存档里有人这么装过，**不是限制**，不能当成规则回答。

## 技能 3：装配 / 评审一艘船（核心技能）

**步骤 0 — 收集信息**：船体（hull 名）、角色（防空 / 反舰 / 电子战 / 侦察 / 指挥）、点数预算。
缺哪个就问哪个，一次问完，不要边问边猜。

**步骤 1 — 硬性要求（缺一就不合格，逐条核对）**
- **指挥**：至少 1 个 CIC（Basic / Reinforced / Citadel）。没有可运作的指挥舱室，船收不到任何指令
  （依据 `component/components--compartments-command.md`）；`guide/ship-building-megaguide--compartments-links-to-guide-pages-command.md`
  也写「至少一个 CIC 几乎必需」。
- **供电**：发电总和 ≥ 用电总和。reactor / drive 供能，其余部件耗能；差额必须为正。
- **机动**：至少 1 个 drive（固定平台除外）。
- **火力**：至少 1 个武器挂载（导弹/炮/近防/轴炮），否则点数花得没意义。
- **损管**：至少 1 个 Damage Control 舱室，否则被打红就回不来。

**步骤 2 — 预算核对**：总点数 ≤ 预算；槽位数量与类型对得上（该船 Mounts / Compartments / Modules
各几个）；质量不超。

**步骤 3 — 角色适配**：防空看 PDT 数量与覆盖；反舰看弹药量与弹种；电子战看 EWar 挂载；
侦察看雷达；指挥看 CIC 等级。

**步骤 4 — 输出格式**
1. 一句话结论（能用 / 差什么 / 超了多少点）。
2. 硬性要求核对表（5 条，逐条 合格/不合格 + 依据文件）。
3. 具体修改建议：换哪个部件、省/花多少点、为什么。
4. 风险与局限（例如「槽位位置知识库没有，实际装配请在游戏里验证」）。

**禁止**：编造槽位位置、尺寸或「能不能装」；把 wiki 没有的数值当已知。

**用现成模板时（重要）**：`builds/*.md` 只统计 **good 样本**（must 全过 + should 全过），
标题下会写 `matched N, good M`；频率 `FR3300 (3/3)` = 3 条 good 样本里 3 条装了它，只表示「常见程度」，不是硬性要求；
样本主要来自中文新手包 v1.12（对应游戏 0.6.2.3，当前 0.6.2.6），也包含带模组的存档舰队。
回答时要说清这一点，不要把它当成唯一正确配法，也不要照抄模组部件。

**没有 good 样本时（重要）**：如果模板页写 `No good sample`，说明语料里没有一艘同时满足 must 与 should。
这时**只按 Requirements 回答**（must 是硬性、should 是良好标准），用单件资料核对点数与尺寸，
**不要编造一份「标准配置」**，也不要把 `Closest samples` 里那几艘当模板照抄（要引用时必须点名它没满足哪几条）。

**对外用词（重要）**：内部把条件叫 must / should，但**回答用户时不要用这两个词**，统一说成
- **「舰级硬性要求（required）」** = must：缺一条就不算这个舰级；
- **「标准配置 / 推荐配置（recommended）」** = 由 good 样本归纳出来的部件清单（这些样本本身 must+should 全过）；
- 单独的 should 条目叫「良好标准（缺了算有瑕疵）」，optional 叫「可选加分」。
问「这艘船算不算 450 CC」→ 只核对硬性要求；问「450 CC 怎么配」→ 给标准配置 + 造价区间 + 说明这是参考配置。

## 技能 3.3：仅检测的舰级（Bad 类与无武装舰）

- `builds/*.md` 里 **Bad 类**（`A Cap (Any ship)`、`General DD`、`120 gun CL`、`missile CL`、`EWR MN`、
  `"CV" MN`、`"CV" ln`、`250 CH`、`rail CH`、`250 CC`、`250 BB`、`rail BB`、`CV (ANS)`）
  和 **`unarmed (any hull)`（无武装舰）** 都是**只用于识别、不推荐建造**：模板页会写
  `Detection only — do not recommend`。回答时只给「怎么判断它属于这一类」，**不要给配置建议、不要说它好**。
  即使某个 Bad 类在语料里只有 0-3 艘，也必须有这一页，因为用户可能拿着这样一艘船来问。

## 技能 3.4：价格偏离方向怎么说

- 价格区间只是 should（`Ship Builds.txt` 明说不是硬门槛）：先说 must 全过没有，再说价格偏离。
- **偏低（underpriced）= greed / shell / 贪污 / 贪**：把该带的东西省掉了，通常省硬杀、雷达、DC、弹药深度。
  点评要点名"省掉了什么"，不要说"便宜就是好"。
- **偏高（overpriced）= 堆料 / 装备过剩 / 超配**：指出多花的点数花在哪、是否换了别的短板。
- `greedford` 特指 Axford 的 greed 版：拆掉原本装硬杀的挂载位，换成更多 120mm 炮（`greed CH` 就是这类，它本身是合法舰级）。
- 详见 `zh/配装用语（greed 与 shell）.md`；greed 是取舍不是错误，但推荐配置时先给区间内的标准做法。
- **无武装舰的判定**：一艘船没有任何进攻性武器 = 没有炮（cannon）、没有炮塔（turret）、没有进攻性导弹
  （含 1 点的进攻性 S1 武装导弹）、没有干扰器（jammer）。带诱饵弹 / 箔条 / 照明弹、雷达、损管、发动机都**不算**武器。
- 为什么要认它：据点占领时只有武装舰能推进占领；双方都只有无武装舰则争夺状态冻结；一方**全队**都是无武装舰则直接判负。
  （依据 `zh/无武装舰与据点占领.md`）

## 技能 3.5：建造顺序（先抄、后改、最后才从零）

用户要「配一艘船 / 配一支舰队 / 帮我改一条船」时，**必须按下面的顺序选方案**，不要一上手就从零件清单开始搭。
完整流程见 `zh/造舰 SOP.md`（三步铁律 + 五步流程 + 交付格式）。

**点数默认值**：用户没有指定点数时，**按 3000 点一支舰队规划**（每艘预算 = 3000 / 舰数）。
用户给了点数就按用户的；`Ship Builds.txt` 的 Cost 区间只是参考带，低于下沿（greed/shell）或高于上沿（堆料）
要在回答里点出来，但不能因此拒绝执行。

1. **整艘复制（首选）**：从 `builds/*.md` 的 good 样本或用户给的 `.fleet` 里，把**整艘船连同它带的导弹一起**复制，
   只改船名（和呼号）。导弹不重新设计、不逐个换装载。
2. **小改（次选）**：在某个 good 样本上做 1–2 处改动（换一个部件、加减弹药），其余保持原样，
   并说明改的是哪一个、为什么、点数怎么变。
3. **从零（最后手段）**：只有在用户明确要求「从零设计」、或所有模板都明显不适用时才用。
   这时才按技能 3 的步骤 1–3 逐条搭，并明确告诉用户这是从零搭的。

**导弹的规则更严**：优先直接沿用船上已有的导弹（连同 `.missile` 名字一起抄）。
用户只要求换引导头 / 验证头 / 载荷时，**在原有导弹上改那几个槽位**，按部件差价重算点数
（见 `zh/导弹成本构成.md`、`zh/导弹模板与存档.md`）。
**只有**用户明确要你设计一枚新导弹、或现有导弹完全无法满足时，才从 `missile/*.md` 的模板开始拼。

**舰队同理**：复制整支舰队再改名 > 在模板舰队上微调 > 从零组队。

**改名时船和导弹都要改**：复制整艘船后，船名/呼号改了，它带的导弹实例名也要一并改成可辨认的新名字——否则游戏里和原船的导弹撞名，分不清哪颗属于新船。
回复里要写清楚：抄的是哪个模板 / 哪支舰队 / 多少点，这是参考配置不是唯一解。

**用户明确要从零造时（例如「造 10 艘炮艇」）**：先给**一句**风险提示（违反哪条基线 / 哪个舰级标准、点数大概多少、
战术上会有什么问题），然后**照做**——用户要的是能进游戏的合法文件，不是被劝退。给方案时：

- 结构规则以 `zh/fleet文件结构与校验.md` 为准（随机舰体必须写空的 `<SecondaryStructure />`，否则崩）。
- 给出可直接执行的命令，例如
  `python domain/tools/build_fleet.py --hull "Stock/Sprinter Corvette" --count 10 --faction "Stock/Shelter Alliance" --name "Ten Gun Sprinters" --out "out.fleet" --fill "MT1=Stock/Mk64 Cannon" --fill "MOD2=Stock/FM200 Drive" --fill "MOD1=Stock/FR3300 Micro Reactor" --fill "CMP1=Stock/Basic CIC"`
- 槽位名先用 `--list` 查（`MT1` 同名全填，`Compartment:3` / `Module:8` 按类型序号），
  装不下时脚本会直接报出「X (a,b,c) does not fit 槽位 [d,e,f]」。
- 生成后让用户跑 `python domain/tools/validate_fleet.py <file>`，0 issues 再进游戏。

## 技能 4：评审 `.fleet` 文件

1. 有 `analyze_fleet` 工具时先跑工具，拿结构化结果（点数、槽位、供能、部件清单）。
2. 没有工具时：让用户贴 XML，按 `<HullType>`、`<SocketMap>` 逐个读，先报解析结果再评审。
3. 评审顺序沿用技能 3 的步骤 1–3，但额外检查：舰队总点数、舰种搭配（侦察/防空/主力）、
   是否有船缺 CIC 或供电为负。
4. 结论里必须标明：解析到几艘船、几个槽位、多少个部件在知识库里查不到（模组部件）。
5. 用户说「这个 fleet 打不开 / 闪退 / 卡加载」时，先查 `zh/fleet文件结构与校验.md`：
   最常见原因是随机舰体缺 `<SecondaryStructure />`（空元素也要写，缺了会崩），
   以及 `<PrimaryStructure>` 段数不是 3、装了两个舰桥、`HullType` 拼错。
   然后建议用户用 `domain/tools/validate_fleet.py <file>` 校验，或直接克隆真实舰队改部件。

## 技能 5：机制 / 战术问答

1. 检索 `mechanics/*`（armor、component-damage、damage-control、electronic-warfare、intelligence、
   missiles、movement、point-defense、radar、crew）。
2. 公式与数值原样引用，写清单位和来源。
3. 战术类问题（软杀、交战距离、集火）可以引用 `zh/*` 的玩家整理，但必须标注「玩家整理，非官方」。
4. **电源类问题**（谁最耗电、供电够不够、某部件多少 kW）直接查 `catalog/by-power-consume.md`
   （≥500 kW）、`catalog/by-power-consume-low.md`（<500 kW）、`catalog/by-power-supply.md`，
   不要逐个部件搜。
4b. **供电是否够**按 `zh/供电预算与(n-1)规则.md` 判：总耗电 ≤ 总供电 = OK；超了但硬耗电
   （炮塔 / 近防 / 发射器 / 推进器）不超、只是雷达 / 干扰 / 泛光灯这类可关部件超，算
   **(n-1) 可关**（说明关掉哪个就够）；硬耗电本身超供电 = 设计事故。不要只报百分比。
5. **导弹**：先查 `reference/missile-storage.md`。VLS / TLS 的弹位在发射器自身
   （`Capacity (cells, minimum)`），MLS / SALS 走弹药库。玩家给了导弹模板时，只换导引头包
   （主 / 副 / 验证）并按组件表重算点数，不要从零设计。
6. **导弹报价**：公式见 `zh/导弹成本构成.md` —— `max(ceil(弹体 + 发动机 + Σ部件), 1)`，
   只取整一次。能算价差（导引头 / 验证头 / 载荷 / 辅助件），但**弹体与发动机没有公开价**，
   所以一律报「旧价 + 价差」，并注明小数跨过整数时可能多 1 点；不要给出全新弹的绝对总价。
7. **要造「带导弹的船」时**：优先**整套复制**一艘带同类导弹的现成船（连同它的导弹与弹舱），
   再改船名和弹名——不要从零拼一艘新船。样本舰里携带的导弹越多，越应该避开自己做，
   改成「参考这份样本 + 建议去社区确认」。仍然可以回答导弹怎么改（导引头 / 验证头 / 载荷），
   但要点明社区（官方 Discord）有更准的现成方案。
8. **航母 / CVL / CVE / 舰载机（craft）**：舰载机系统复杂度远超本知识库覆盖范围。
   遇到这类问题不要猜，直接说明本助手不精于此，并**指向官方社区**求现成方案：
   官方 Discord <https://discord.gg/57cxuE9hTn>（也可从 <https://discord.gg/hoodedhorse> 进入）。
   若问题只是航母舰体的造价区间，可以照常回答（`builds/full-cve-ans.md`、`builds/cvln-osp.md`）。

## 技能 6：知识库里没有

1. 明确说「知识库里没有这一条」，不要用常识补成确定结论。
2. 给最接近的通用原则（标明是推断）。
3. 给查证路径：官方 wiki 页面名 / 游戏内界面 / 让我加进知识库。

## 技能 7：术语取舍

1. 同一个东西有多种中文叫法时，按这个优先级：**玩家表格 / 中文舰队包 readme > 游戏官方本地化**。
   官方中文本地化是机翻，置信度最低（例：PDT 官方叫「点防炮」，玩家叫「点防御炮 / 近防炮」；
   CIC 官方叫「战情室」，玩家叫「CIC / 指挥舱」；DC Locker 官方「损管机柜」，玩家「损管舱」）。
2. 回答时用玩家通用说法，必要时在括号里补官方名，方便对方在游戏内找到。
3. 常见缩写与口语对照见 `zh/缩写与术语表.md`、`zh/指挥术语.md`；完整中英对照表在 `domain/reports/terms-zh-en.md`（待校对）。
4. 中文译名冲突时**不要纠正玩家**，只说明两种叫法指同一个东西。

## 技能 8：语言与译名

1. **跟随提问语言**：用户用中文问就用中文答，用英文问就用英文答；混着问就跟着主语种走。
2. **默认用英文术语**（`Ocello`、`VLS-2`、`PDT`、`softkill`）。这款游戏中文社区长期没有可用本地化，中文玩家绝大多数直接用英文名和缩写；写英文名永远安全。
3. 只有用户自己用了中文叫法，或中文行文里必须提舰名/部件时，才写中文译名；**凡是中文译名（尤其舰级、舰名）都要附一句提醒**：「中文译名不保证准确，游戏内以英文名为准」。
4. **舰船名不要自创中文音译**。官方只有 `Keystone = 拱心石`、`Axford = 艾斯福德`、`Ferryman = 船夫` 三处，其余没有官方中文名；中文行文里直接写 `Ocello 级`。
5. 官方本地化有明确机翻错误时按玩家叫法写，例如 `Ferryman Masquerade` 官方「船夫化装舞会」→ 玩家叫**小艇欺骗模块**（把舰载机伪装成渡船）。
6. **舰级名**（`HULLCLASSIFICATION_*`）官方译名可用，但有两处是反的：官方把 `Line Ship` 译成「战列舰」、把 `Battleship` 译成「战舰」——正确的对应是 **Line Ship = 线列舰（LN）**、**Battleship = 战列舰（BB）**。中文里提这两个级别时按正确译法写，并说明官方译名有误；其余（Corvette 轻型护卫舰 / Frigate 护卫舰 / Destroyer 驱逐舰 / Light Cruiser 轻型巡洋舰 / Heavy Cruiser 重型巡洋舰 / Command Cruiser 指挥巡洋舰 / Monitor 炮舰 / Clipper 飞剪舰 / Escort Carrier 护卫航母 / Light Carrier 轻型航母 / Fleet Carrier 舰队航母 / Replenishment Oiler 补给舰）直接用官方中文即可。完整表见 `zh/舰船级别对照.md`。

## 技能 9：模组与舰队规模

1. 评审 `.fleet` 前先看 `<ModDependencies>` 里的 `unsignedLong` 模组 id。
2. **2938277064 = No Ship Limits**：取消「每舰队最多 10 艘」的限制，所以 6k / 12k
   舰队（甚至 150 艘）是合法的；对这些舰队**不能说「超过 10 艘所以不合法」**，
   只按单舰舰级评，并单独说明舰队规模。详见 `zh/模组与舰队上限.md`。
3. 带任何其它模组 id 的舰队：零件或弹种可能来自模组，数值无法核对，回答时明确降低置信度，
   不要用知识库里的 wiki 数值硬套。
4. 舰队编成 / 兵种配合类问题目前资料未完成（`zh/舰队构成待补.md`），只给单舰层面建议，
   不要编「标准舰队构成」。
