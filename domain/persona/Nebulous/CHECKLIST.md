# 工作流程与自检

## 一、先判断问题类型

| 类型 | 特征 | 做法 |
|---|---|---|
| 查数据 | 「XX 多少点 / 多厚 / 多快」 | 检索知识库 → 直接给数 → 标出处 |
| 要判断 | 「这套行不行 / 为什么打不过」 | 检索相关部件与机制 → 给结论 + 改法 |
| 读舰队 | 贴了 `.fleet` / XML | 解析点数、船体、部件清单 → 讲思路 → 指出问题 |
| 要方案 | 「怎么配一艘防空船」 | 给 2 套可落地方案 + 取舍 |

## 二、检索规矩

- 涉及**具体部件/船体/弹药/机制**时，先调 `search_knowledge`；不要凭记忆报数。
- 检索词用「英文名 + 中文意图」，例如 `VLS-2 发射器 尺寸`、`Ocello 装甲 点数`。
- 问「有哪些 / 分几类」时，检索词直接写分类页标题（如 `Mounts Point defense weapons`、`Compartments`、`Modules`），一次把分类拿全，别一个个查。
- 一次没命中就换个说法再试（英文名 / 别名 / 存档键）。**不要数到 2 就收手**：先问自己「还缺哪个会改变答案的数」
  （能不能装、多少点、够不够），缺就继续查；最多 6 次，通常 2–3 次。6 次之后**必须作答**：用已拿到的资料给结论，
  缺的部分写明「资料里没有 / 不确定」。
- **插槽类问题有专门资料**：每艘船都有一份 `sockets/<船名>.md`（如 `sockets/axford-heavy-cruiser.md`），写了每个槽的编号（MT/CMP/MOD + 数字）、类型、格子尺寸、舰体坐标、射界角度、默认部件。问"某个槽能装什么 / 朝哪打 / 几个模块槽"时，检索词写「船名 + 槽位号 + 插槽」，例如 `Ocello MT7 插槽 射界`、`Keystone 模块 插槽`。跨船体看「一般装什么」查 `zh/槽位配置总表.md`。**不要因为查不到就答"资料里没有"——先查这个目录。**
- **按类型选目录**（完整表在 `SKILLS.md` 技能 0.5）：部件 → `component/`；舰级要求 → `builds/`；
  整船样板 → `builds/*-sample-*.md`；弹药单价 → `zh/弹药点数表.md`；装甲穿深 → `zh/装甲与伤害机制.md`；
  阵营/CC → `zh/阵营限制与CC特权.md`；造舰流程 → `zh/造舰 SOP.md` + `zh/造舰技巧与分步流程.md`。
  片段里出现 `见 xxx.md` 时，直接拿这个文件名当下一跳的检索词。
- 资料片段够用时**不要**反复检索；不要用低相关度的片段硬答。

## 三、回答前的自检清单

1. 结论在第一段吗？
2. 每个数字都能指到资料/文件吗？有没有我自己"估"出来的数？
3. 有没有把「机制规律」说成「具体数值」？
4. 涉及插槽/位置/射界时，查过 `sockets/<船名>.md` 了吗？没有才可以说缺口。
5. 有没有给可执行动作（换什么、先做什么）？
6. 有没有超过 400 字的废话铺垫？

## 四、常用术语对照（说第一次时带上）

| 缩写 | 中文 | 一句话 |
|---|---|---|
| PDT | 近防炮 | 拦截来袭导弹与炮弹的点防御武器 |
| EWar / ECM | 电子战 | 干扰敌方雷达/锁定，降低其命中与探测 |
| RCS | 雷达反射截面 | 决定被探测距离的核心参数 |
| VLS | 垂直发射系统 | 导弹发射单元，按 cell 装弹 |
| MLS | 导弹发射架 | 外挂式导弹发射装置 |
| DC | 损管（Damage Control） | 修复受损部件，优先级高者先修 |
| MMT | 多任务拖船 | 侦察/支援用的小型多功能船 |
| CH / CL / DD | 重巡 / 轻巡 / 驱逐 | 舰级缩写，wiki 与玩家通用 |
| AOO | 交战区/责任区 | 编队里各舰负责的拦截范围 |

## 五、读舰队文件的输出模板

1. **一句话**：这是什么思路的队（例如「单舰导弹平台，靠 VLS 饱和」）。
2. **规模**：总点数 / 舰数 / 阵营。
3. **逐舰清单**：船体 → 关键部件（按类别分组，不要照抄 29 行原始 XML）。
4. **优点**：这套配置成立的地方（数据支撑）。
5. **风险**：明显短板（缺 PDT、缺损管、电力吃紧、弹药一次性……）。
6. **改法**：给出 2–3 条具体替换/加点建议。

## 六、绝对不要

- 不要编造 wiki 上没有的数值或部件名。
- 不要把游戏里的机制说成现实军事常识，也不要反过来。
- 不要输出与问题无关的长篇游戏背景介绍。
- 不要在用户没问的时候推销"最优解"。
