# 造舰技巧与分步流程

> 关键词：满套软杀、软杀组合、互补、两艘船分工、greedford 双舰、造舰技巧、分步流程、自检清单。
> 定位：`Ship Builds.txt` 说**必须有什么**，`造舰 SOP v0.2` 说**按什么顺序做**，这一页补
> **怎么把两艘船配成一套**、以及**每一步怎么自检**。
> 证据标注：【存档】= 从 `Saves/Fleets` 统计、真实舰队里出现；【规则】= `Ship Builds.txt` 原文；
> 【推算】= 由数值推导（会写出算式）。

## 1. 满套软杀：不是「带一个干扰机」

「满套软杀」指对方**锁不上、打不准、打不中**这三件事同时被压住。分工具看：

| 工具 | 代表部件 | 作用（英文原文关键词） | 存档里的常见位置 |
|---|---|---|---|
| 干扰机 | `E70 'Interruption' Jammer` | 打断敌方锁定链路（jam / lock break） | 一个中槽，几乎每艘成型船一个 |
| 箔条 | `EA12 Chaff Decoy` | 让雷达制导导弹丢目标（chaff / radar decoy） | `VLS-1-23` 发射器，19–20 发 |
| 照明弹 | `EA20 Flare Decoy` | 骗红外/光学制导（flare） | 与箔条同发射器，1–4 发 |
| 强光照明 | `E57 'Floodlight' Illuminator` | 压制光学观测、点亮对面（illuminate） | 小槽，常与小 DC 放一排 |
| 点防 | `Mk20 'Defender' PDT` | 末端硬杀（PD / 20mm） | 2×2×2 或 3×3×3 模块 |
| 反导探测 | `ES32 'Scryer' Missile ID System` | 提前识别来袭导弹（missile identification） | 中槽 |
| 远程雷达 | `RS41 'Spyglass' Radar` / `RM50 'Parallax' Radar` | 先看见 = 先锁定（LRT radar / fire control） | 中槽 |

**判定「满套」的实用标准**（按 3 000 点两艘船算）：2 个干扰机、2 个箔条发射器、至少 1 个照明弹
发射器、2 个点防、2 个雷达（其中 1 个是火控/远程），再谈火力。少于这个数，就别在 KB 里写
「软杀 OK」。

## 2. 成对互补的四条规则（软杀组合怎么分）

1. **每艘船自带干扰 + 箔条**，不要把软杀集中在一艘上。对方先手打掉指挥船时，另一艘还能继续软杀。
2. **剩余槽位分工，而不是复制**：一艘补火力（导弹发射器、备用弹药），一艘补预警（反导探测、远程雷达）。
3. **硬杀可以不对称**：双 450 是 `Ship Builds` 的 must，两艘都要有；120mm 数量可以 3 门 / 4 门。
4. **两艘 1 500 比一艘 3 000 稳**：单船被集火就没了，两船至少还有一半软杀与一半火力。

## 3. 实例：greedford 双舰（`York Supreme` + `Equility-On-Sea`）

来源：`Saves/Fleets/Imported/greedford.fleet`，两条都是 Axford 重巡（1 440 + 1 560 = **3 000 点整**）。
「greedford」= 把原本用于硬杀的挂载换成更多 120mm 炮的贪配 Axford —— 这两条正是**贪配但仍然把
软杀做满**的范例。

### 完全相同的部分（软杀骨架）

| 槽位 | 部件 | 说明 |
|---|---|---|
| MT1 | `E70 'Interruption' Jammer` | 每艘一个，不省 |
| CMP5 | `Mk66 Cannon`（450） | must：双 450 之一 |
| MOD11 | `Mk68 Cannon`（450） | must：双 450 之二 |
| MOD3/MOD7 | `Mk20 'Defender' PDT` + `RF101 'Bullseye' Radar` | 两艘都有，只是槽位互换 |
| CMP8 / MOD8 / CMP2 / MOD4 / MT5 / MOD5 | Reinforced CIC、Reinforced DC Locker、Small/Rapid DC Locker、Large DC Locker、Damage Control Central | 损管套件完全相同 |
| MT2 / MOD10 | `Auxiliary Steering` ×2 | 转向冗余 |
| MT9 / CMP10 | `FR4800` + `FR3300 Micro Reactor` | 双反应堆 |
| MOD2 / CMP11 | `FM230 'Whiplash'` + `FM580 'Raider'` | 双驱动 |
| MT8 / CMP3 / CMP6 | `Ammunition Elevators` ×3 | 射速加成（`0.85^n` 叠加） |

### 不同的部分（分工）

| 槽位 | York Supreme（1 440） | Equility-On-Sea（1 560） | 分工含义 |
|---|---|---|---|
| MT4 | `Mk62 Cannon` | **`VLS-2 Launcher`（13 发导弹）** | 第二艘加导弹火力 |
| MT3 / MT7 | `Gun Plotting Center` / **`Reinforced Magazine`** | **`Reinforced Magazine`** / `Gun Plotting Center` | 弹药与火控互换槽位 |
| MOD1 / CMP1 | `VLS-1-23`（箔条 19 发）/ `E57` | `E57` / `VLS-1-23`（箔条 20 + **照明弹 1**） | 第二艘多带照明弹 |
| CMP4 | `Mk62 Cannon` | `Mk62 Cannon`（不同槽，数量一致） | — |
| MT6 / MT11 | `Ammunition Elevators` / **`RM50 'Parallax' Radar`** | `FR3300` / `Ammunition Elevators` | 第一艘补火控雷达 |
| CMP7 / MOD12 | —（空） | **`ES32 'Scryer'` + `RS41 'Spyglass'`** | 第二艘补反导/远程预警 |
| CMP9 | `Bulk Magazine`（120-RPF 400 / HE 600 / AP 400） | `Bulk Magazine`（120-RPF 700 / HE 1000 / AP 800） | 第二艘多 750 发 120mm |

**结论**：两条船的软杀骨架（干扰、箔条、照明、点防、损管）完全一致，只在**剩余槽位**上分叉 ——
一艘换火控雷达，一艘换导弹 + 反导探测 + 更多 120mm 备弹。这就是 `Ship Builds.txt` 里
「两艘好软杀船带互补工具达成满套软杀」的落地形态。

## 4. 分步流程（照这个顺序做，每步有检查点）

1. **读 must**：`builds/<舰级>.md` 的 MUST 表，逐条抄下来当硬约束（点数、双 450、硬杀/软杀…）。
2. **选船体**：`hulls/<hull>.md` 看槽位表（`MT` 挂载 / `CMP` 舱室 / `MOD` 模块）与装甲、内置雷达。
3. **先抄样本**：`builds/<舰级>-sample-N.md` 是真实存档的逐槽表 —— **整艘复制 > 轻改 > 从零拼**（SOP 铁律）。
4. **改名**：船名、呼号**和导弹名**一起改（导弹模板名不改，两条船会互相覆盖）。
5. **换部件**：按 `zh/槽位配置总表.md` 的「常用部件」列替换，尺寸必须 ≤ 槽位尺寸（对角摆放另算）。
6. **装弹库**：`zh/弹药装载与弹库规则.md` —— 弹库容量 = 格数 × 系数（Bulk 15 / Reinforced 10 / Citadel 10×格数÷3）。
7. **装弹药**：`zh/弹药点数表.md` —— 炮弹按每点发数、导弹按每发点数、诱饵 EA12=1 / EA14=2 / EA20=1 / EA99=8。
8. **算供电**：发电 ≥ 耗电，留 10 % 余量；`power` 正数是发电、负数是耗电。
9. **补损管与机动**：DC Locker 一层、Aux Steering 一对、双驱动（大驱动 + 微驱动）。
10. **验证**：`validate_fleet.py`（槽位尺寸、阵营、供电、必需件），再看 `zh/造舰 SOP.md` 的自检清单。

## 5. 常见坑（都是踩过的）

- **`.fleet` 少模板库**：舰队根节点必须有 `<MissileTypes>` / `<CraftTypes>`，船上的发射器与机库按
  `$MODMIS$/SGM-100 ARM`、`$CRAFT$/B-45 Sturgeon` 去里面取模板。只搬 `<Ship>` 的话进游戏会报
  `Fleet is missing guide with GUID …`，导弹与舰载机全部不加载。
- **`<InitialFormation><GuideKey>` 指向别的船**：手工拼舰队时换了 `<Key>` 却忘了换向导键，游戏会报
  `The ship X will start independently`。单船文件里向导就是自己。
- **垃圾部件**：贪心算法爱塞 Missile Programming Bus、Analysis Annex、三个雷达 —— 每件都占点数却不产
  生战斗力。
- **弹库不计价**：第一个弹库免费、其余按最贵的一个计费；点数是「船 + 部件 + 弹库 + 弹药」，只算前两项会低估 100–200 点。
- **阵营混装**：`FactionKey` 是舰队级的，SA 部件装进 OSP 舰队会被踢；只有 **CC（Ocello）** 有跨阵营特权。
- **照抄负样本**：`(bad)` 舰级的样本是反面教材，KB 里标题写着 `Detection only`，别当推荐。

## 6. 自检清单（造完一艘船，逐条打勾）

- [ ] 舰级 must 全中，点数落在区间内（`Ship Builds.txt` 的区间，不是硬上限）
- [ ] 每个槽位：尺寸装得进、阵营合法、不是垃圾件
- [ ] 双 450（或该舰级的硬性武器）到位，弹药装进弹库
- [ ] 供电有余量、驱动与转向成对、DC 覆盖全船
- [ ] 船名 / 呼号 / **导弹名**都改过
- [ ] `validate_fleet.py` 无 error
