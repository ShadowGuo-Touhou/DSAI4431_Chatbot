# 导弹成本构成（按源码）

## 1. 总价公式

`ModularMissile.PointCost`（源码 117571 行）：

```
cost = max( ceil( 弹体价 + 发动机价 + Σ(每个插槽里的部件价) ), 1 )
```

- **只取整一次**，作用在合计上，不是每项各自取整。
- 所以改一个部件时「新价 = 旧价 + 价差」，但小数部分跨过整数时会多 1 点——这就是「极端配置会贵 1 点」的机制。

## 2. 部件价

`MissileComponentDescriptor.PointCost`（123736 行）：

```
部件价 = _pointCost × 弹体.UniformCostScaling
```

原版弹体的 `UniformCostScaling` 都是 1.0，所以部件价就是自己的 `_pointCost`；wiki 的
「Base Cost / Validator Cost」两列就是这两个数。

导引头（125858 行）：`Mode=Targeting` 收 Base Cost，`Mode=Validation` 收 Validator Cost。
例：Fixed Active Radar 1 / 0.25，Electro-Optical 8 / 5，Wake-Homing 0.25 / 0.5。

## 3. 发动机价（123961 行）

```
发动机价 = lerp(速度代价区间, BalanceValues.A)
         + lerp(推力代价区间, BalanceValues.C)
         + lerp(飞行时间代价区间,  BalanceValues.B)
```

每条弹的 A/B/C 配比都不同，所以同弹体的两条弹价格也会不同。

## 4. 制导与反辐射（126641 / 126340 行）

- `制导价 = 基础价 + 机动代价表[Maneuvers]`（终端机动按档加价）。
- 反辐射导引头再乘一层 `目标类型代价倍数[All / Jamming / Pulsed]`。

## 5. 已知 / 未知

| 项 | 状态 |
|---|---|
| 25 个导弹部件 Base / Validator 价 | **已知**（官方 wiki） |
| 弹体 `_pointCost` | 未知（Unity 资源里，源码与 wiki 都没有） |
| 发动机三个代价区间 | 未知（同上） |
| 机动代价表、目标类型倍数 | 未知（同上） |

结论：**能算价差**（换导引头 / 验证头 / 载荷 / 辅助件），**不能算全新弹的绝对总价**，
换发动机配比只能给区间。

## 6. 怎么变成精确值

游戏导弹设计器有 **Point Cost Breakdown**（源码 119027 行），逐行列出 `+X: 弹体`、`+Y: 部件`。
把那一屏的数字给到 `domain/data/missile_body_engine.json`，总价就能精确计算。

## 7. 回答规矩

- 先说模板现价，再说改动项与价差，最后给「新价 = 旧价 + 价差」，并注明可能 +1。
- 不要用 wiki 价推一条全新弹的总价；弹体、发动机一律说没有公开价，不要编。
- 只做「改模板」，不从零设计，不碰舰载机（craft）相关组合；缺失组合不要凭空补。
