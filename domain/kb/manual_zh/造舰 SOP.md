# 造舰 SOP（配船 / 配舰队 / 改船的执行顺序）

Keywords: 造舰, 配船, 配舰队, 改船, 抄模板, 从零, 铁律, 优先级, 默认点数, SOP, 流程
Summary: 整艘复制 > 小改 > 从零；must 全过 > should 尽量全过 > optional 有余量再加；没给点数时默认 3000 点一支舰队。
Tags: kind=guide; lang=zh; topic=ship building workflow

面向：舰队参谋（大肥鱼）在回答「帮我配一艘船 / 配一支舰队 / 改一条船」时使用。
本文件是 other info 里的可编辑稿，定稿后会转成知识库里的 zh/造舰 SOP.md。

────────────────────────────────
0. 默认值（没有说明就按这个来）
────────────────────────────────

- 点数：用户没给预算时，**默认按 3000 点一支舰队**规划（每艘预算 = 3000 / 舰数）。
  用户给了点数就按用户的；Ship Builds.txt 的 Cost 区间只是参考带，低于下沿（greed/shell）
  或高于上沿（堆料）要在回答里点出来，但**不能因此拒绝执行**。
- 舰数：用户没说就按「够用即可」给 2–4 艘，并说明可扩展方向。
- 语言：默认中文，部件/舰级用游戏英文名（450 CH、Mk66 Cannon、VLS-2），
  中文名只作解释。舰级中文名以知识库的官方译名为准，并注明官方翻译可能不准。

────────────────────────────────
1. 三条铁律（顺序不能反）
────────────────────────────────

铁律一：**整艘复制 > 小改 > 从零**
  1) 优先从 builds/*.md 的 good 样本或用户给的 .fleet 里，**整艘船连同它带的导弹一起复制**，只改船名/呼号。
     检索时**直接查「<舰级> 样板船完整装配」**（例如「450 CH 样板船完整装配」），
     结果里会有 `builds/<舰级>.md › 样板船完整装配（整艘照抄）` 这一段：
     逐槽表（槽位/部件/尺寸/点数/供电）+ 合计点数 + 供电余量 + 弹库装载都在里面，照着它抄。
     同一页的「部件频率表」只是统计，**不是**任何一艘船的实际配装，不要拿它自己拼。
  2) 其次在某个 good 样本上做 1–2 处改动，说明改哪、为什么、点数怎么变。
  3) 只有用户明确要求从零、或所有模板都不适用时，才从零件清单开始搭，并明确说「这是从零搭的」。

铁律二：**must 全过 > should 尽量全过 > optional 有余量再加**
  - must：舰级的硬性要求（Ship Builds.txt 的 must），缺一条就不算这个舰级。
  - should：良好标准，有瑕疵仍算该舰级，但要在回答里指出瑕疵。
  - optional：加分项，点数有余量才加，加之前先说清楚换掉什么。
  - 通用基线（每艘船都要过）：drive / CIC / ammo storage / 供电 < 110%（(n-1) 规则）/ 弹药量；
    Avoid 四条：engineering 模块、>1 内部雷达、>2 弹药库、TLS 发射器。

铁律三：**导弹跟着船走，别重新设计**
  - 复制整艘船时导弹一起复制；**导弹也要改名**——船改名后，导弹实例名一并改成可辨认的新名字。
  - 用户只要求换引导头/验证头/载荷时，在**原有导弹**上改那几个槽位，按部件差价重算点数。
  - 只有用户明确要设计新导弹、或现有导弹完全无法满足时，才从 missile/*.md 的模板拼。

舰队层面同理：复制整支舰队再改名 > 在模板舰队上微调 > 从零组队。

2. 五步流程（每次造舰都走一遍）
────────────────────────────────

第 1 步：定需求
  - 问清：舰级？点数？舰数？用途（主炮线列 / 导弹 / 防空 / EWR / 支援 / 抢点）？
  - 用户没说的用第 0 节的默认值，并在回答开头一句话说明「我按 3000 点 / N 艘来做」。

第 2 步：找模板（先检索，再动手）
  - 检索 builds/<舰级>.md：看 good 样本数、核心件（k/good）、供电中位、价格中位。
  - 没有 good 样本时：**不要编标准配置**，按 Requirements 逐条回答，并列出「最接近的样本缺什么」。
  - 需要槽位数据时查 sockets/<hull>.md（尺寸/数量/左右/默认件）。

第 3 步：套基线 + 舰级 must
  - 逐条对 must，标 ✔ / ✘ / 未知；未知要么去查数据，要么如实说「这个条件我判断不了」。
  - 通用基线：供电按 (n-1) 算（能关的部件关掉后不超载），drives 也供电，PCC/SRB 提升反应堆效率。
  - 硬性不达标就不要说「达标」；用户坚持要就这样做，但必须写清违反了哪条。

第 4 步：填 should 与 optional
  - 按 should 清单补：雷达、强化弹药库、arming missile、弹药时长、损管、软/硬杀。
  - optional 按预算余量加，每加一件说明「换掉什么 / 加多少点」。

第 5 步：算账 + 交付
  - 点数：船体 + 部件 + 弹药 + 导弹（导弹按模板或部件差价算），逐件列出单价。
  - 供电：列出常开负荷 / 可关负荷 / 干扰器负荷、发电量（含 PCC/SRB 效率）、余量。
  - 槽位：说明每件装在哪个槽（几号挂载位 / 哪个舱室），装不下就换件，不要硬塞。
  - 交付物：可复制的 build_fleet.py 命令 + validate_fleet.py 校验结果（0 issues），
    或整份 .fleet 文件；并注明「这是参考配置，不是唯一解」。

────────────────────────────────
3. 回答格式（推荐）
────────────────────────────────

一句话结论 → 舰队编成表（舰名/舰级/点数/用途）→ 每艘的部件表（部件/槽位/点数/供电）→
供电与弹药小结 → 风险与可改项 → 交付命令 / 文件路径。

────────────────────────────────
4. 常见错误（自查清单）
────────────────────────────────

[ ] 有没有把 must 未过的船说成「符合该舰级」？
[ ] 有没有在没 good 样本时编一份「标准配置」？
[ ] 导弹是不是重新设计了（应该整套复制或只换槽位）？
[ ] 点数是不是只报总价、没给逐件单价？
[ ] 供电是不是只报百分比、没按 (n-1) 算？
[ ] 槽位尺寸/类型有没有核对（装不下会被游戏静默留空）？
[ ] 有没有写清「参考配置，不是唯一解」？

────────────────────────────────
5. 待定 / 需要作者确认
────────────────────────────────

- 默认点数 3000 是否适用于单舰问答（还是只在「配一支舰队」时用）。
- 是否需要「先给 2 个方案再让用户选」的硬性要求。
- greed / shell 的判定阈值（比价格带低多少算 greed）。
